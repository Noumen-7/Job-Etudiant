================================================================================
1. VUE D'ENSEMBLE DU SYSTÈME
================================================================================

JobEtudiant est une application web full-stack qui met en relation :
  - des ÉTUDIANTS (consulter offres, postuler, suivre candidatures)
  - des ENTREPRISES (publier offres, recevoir et traiter candidatures)

Deux rôles distincts (enum Role) : ETUDIANT | ENTREPRISE
Chaque compte User possède UN profil lié : Etudiant OU Entreprise (relation 1:1).

Couches logicielles :
  [Navigateur] → [Pages React / App Router] → [API Routes] → [Prisma ORM] → [PostgreSQL]
  Services transverses : JWT (auth), Notifications (polling client), Upload fichiers

Stockage fichiers (local) :
  public/uploads/avatars/  → photos de profil
  public/uploads/cv/       → CV (profil + candidatures)
  Servis via API : /api/avatars/[filename] et /api/cv/[filename] (pas d'accès direct public)

2. ARCHITECTURE GLOBALE
================================================================================

2.1 Schéma de flux données
--------------------------

  Navigateur (client)
       │
       ├─ Pages protégées (/etudiant/*, /entreprise/*)
       │     └─ proxy.ts vérifie cookie JWT + rôle
       │
       ├─ Pages publiques (/, /auth/*)
       │
       └─ fetch() → API Routes (/api/*)
             ├─ lib/auth.ts → requireAuth() / requireRole()
             ├─ lib/prisma.ts → base de données
             └─ lib/*.server.ts → logique serveur (fichiers, notifs offre)

2.2 Arbre des providers (côté client)
-------------------------------------

  app/layout.tsx
    └─ providers/Providers.tsx
         ├─ ThemeProvider        → thème clair/sombre (localStorage)
         ├─ AuthProvider         → état utilisateur, refetch, logout
         └─ NotificationsProvider → polling 15s, toasts, mark read

2.3 Double protection des routes
--------------------------------

  Niveau 1 — src/proxy.ts (Next.js 16, remplace middleware.ts)
    Routes publiques sans token :
      / , /auth/* , /api/auth/* , /api/avatars/* , /api/cv/*
    Autres routes : cookie "token" obligatoire
    Rôle ETUDIANT requis pour /etudiant/*
    Rôle ENTREPRISE requis pour /entreprise/*

  Niveau 2 — Chaque API handler
    lib/auth.ts : requireAuth() ou requireRole('ETUDIANT'|'ENTREPRISE')
    Vérifie le JWT depuis le cookie httpOnly côté serveur

2.4 Modèle de données (Prisma)
------------------------------

  User (1) ──(0..1)── Etudiant
  User (1) ──(0..1)── Entreprise
  User (1) ──(*)──── Notification

  Etudiant (1) ──(*)── Candidature ──(*)── Offre (1) ──(*)── Entreprise

  Modèles :
    User         : email, password (bcrypt), role, resetToken, resetTokenExp
    Etudiant     : nom, prenom, telephone, description, portfolio, linkedin,
                   domaine, avatarUrl, cvUrl
    Entreprise   : nom, secteur, description, site, telephone, adresse, avatarUrl
    Offre        : titre, description, domaine, type, lieu, remuneration,
                   isActive, dateFin, createdAt, updatedAt
    Candidature  : cvUrl, message, statut (EN_ATTENTE|ACCEPTE|REFUSE)
                   contrainte unique (etudiantId, offreId)
    Notification : titre, message, isRead, createdAt

  Enums : Role, StatutCandidature

3. FLUX MÉTIER GLOBAUX (INTERACTIONS SYSTÈME)
================================================================================

3.1 Visiteur non connecté
-------------------------
  GET / → app/page.tsx
    → getCurrentUser() (lib/auth.ts + lib/jwt.ts)
    → si connecté : redirect selon rôle
    → sinon : components/landing/LandingPage.tsx

3.2 Inscription
---------------
  LandingPage → lien /auth/register?role=ETUDIANT|ENTREPRISE
  auth/register/RegisterForm.tsx
    → POST /api/auth/register
       → prisma.user.create + nested etudiant OU entreprise
       → bcrypt.hash(password)
       → signToken() → cookie httpOnly "token" (7 jours)
       → prisma.notification.create (bienvenue)
    → AuthProvider.refetch() → GET /api/auth/me
    → redirect /etudiant/accueil ou /entreprise/dashboard

3.3 Connexion
-------------
  auth/login/page.tsx
    → POST /api/auth/login
       → prisma.user.findUnique → bcrypt.compare
       → signToken() → cookie
       → notif "Bon retour" si absente depuis 24h
    → refetch() → redirect selon rôle

3.4 Déconnexion
---------------
  Navbar → AuthProvider.logout()
    → POST /api/auth/logout → suppression cookie
    → redirect /auth/login

3.5 Mot de passe oublié
-----------------------
  auth/forgot-password/page.tsx
    → POST /api/auth/forgot-password
       → resetToken + resetTokenExp en DB
       → lib/email.ts (Nodemailer SMTP)
  auth/reset-password/page.tsx
    → POST /api/auth/reset-password
       → validation token → bcrypt.hash nouveau MDP

3.6 Publication d'une offre (entreprise) + recommandation par domaine
-------------------------------------------------------------------
  entreprise/offres/page.tsx → OffreModal
    → POST /api/entreprise/offres
       → requireRole('ENTREPRISE')
       → prisma.offre.create (avec dateFin)
       → lib/offre.server.ts : notifyEtudiantsForNewOffre(domaine, titre, nom)
          → prisma.etudiant.findMany WHERE domaine = offre.domaine
          → prisma.notification.createMany pour chaque étudiant concerné

  Étudiant voit l'offre :
    etudiant/metier/page.tsx → GET /api/offres
       → filtre isActive + dateFin non expirée (lib/offre.ts)

3.7 Candidature (postuler)
--------------------------
  etudiant/metier/page.tsx → PostulerModal
    → GET /api/etudiant/profil (récupère cvUrl par défaut)
    → POST /api/etudiant/candidatures (FormData)
       → requireRole('ETUDIANT')
       → lib/offre.isOffreExpired() — refuse si offre expirée
       → CV : useDefaultCv → lib/cv.server.copyCvForCandidature()
              OU upload → lib/cv.server.validateCvFile()
       → prisma.candidature.create
       → prisma.notification.create → entreprise ("Nouvelle candidature")

3.8 Traitement candidature (entreprise)
---------------------------------------
  entreprise/reception/page.tsx
    → GET /api/entreprise/candidatures
    → PUT /api/entreprise/candidatures/[id] { statut: ACCEPTE|REFUSE }
       → prisma.candidature.update
       → prisma.notification.create → étudiant

3.9 Consultation CV
-------------------
  etudiant/demandes/page.tsx | entreprise/reception/page.tsx
    → lib/cv.resolveCvUrl(cvUrl) → URL /api/cv/[filename]
    → components/cv/PdfViewerModal.tsx (fetch blob → iframe, pas téléchargement)

3.10 Photo de profil
--------------------
  etudiant/profil/page.tsx | entreprise/profil/page.tsx
    → components/profile/AvatarUpload.tsx
       → AvatarCropModal (recadrage canvas → blob JPEG)
       → POST /api/*/profil/avatar (FormData)
          → lib/avatar.server.validateAvatarFile()
          → écriture public/uploads/avatars/
          → lib/avatar.buildAvatarUrl() → update DB avatarUrl
       → DELETE pour suppression
    → ProfileAvatar → lib/avatar.resolveAvatarUrl() → GET /api/avatars/[filename]

3.11 CV par défaut (profil étudiant)
------------------------------------
  DefaultCvUpload → POST /api/etudiant/profil/cv
    → lib/cv.server.validateCvFile() → public/uploads/cv/ → etudiant.cvUrl

3.12 Notifications (cycle complet)
----------------------------------
  CRÉATION (serveur) :
    - register : bienvenue
    - login : bon retour (si > 24h)
    - candidature : notif entreprise
    - statut candidature : notif étudiant
    - nouvelle offre : notif étudiants même domaine

  LECTURE (client) :
    NotificationsProvider → GET /api/notifications toutes les 15s
    → Navbar (badge unreadCount)
    → */notifications/page.tsx → NotificationsContent
    → Toast pour nouvelles non lues

  ACTIONS :
    PATCH /api/notifications/[id] → marquer lue
    PUT /api/notifications → tout marquer lu

3.13 Dashboard entreprise
-------------------------
  entreprise/dashboard/page.tsx → GET /api/dashboard
    → requireRole('ENTREPRISE')
    → agrégats : offres publiées, candidatures par statut

9. POINTS TECHNIQUES IMPORTANTS
================================================================================

  - Prisma 7 : DATABASE_URL dans prisma.config.ts, pas dans schema.prisma
  - Next.js 16 : proxy.ts (pas middleware.ts) pour protection routes
  - JWT en cookie httpOnly "token" — non accessible en JavaScript client
  - Séparation client/serveur : *.server.ts pour code Node (fs, validation fichiers)
  - avatar.ts / cv.ts = URLs côté client ; avatar.server.ts / cv.server.ts = disque
  - Une candidature = un CV copié ou uploadé (cvUrl sur Candidature, pas seulement profil)
  - Recommandation = matching domaine offre ↔ domaine étudiant (pas d'IA)
  - dateFin null = offre sans expiration ; backfill met +90j sur anciennes offres
